# 原工作台音乐播放功能设计

## 目标

在现有 `http://127.0.0.1:8765/` 工作台中增加真正可用的音乐播放能力。用户搜索歌曲后，可以直接播放、控制进度、管理播放队列，并在播放与商品制作之间无缝切换。现有搜索、封面抓取、单曲制作、热门批量制作和作品库保持原有数据结构与行为。

本设计面向后续客户和公众使用。播放器只消费工作台后端明确标记为可播放的音频地址，不从网页抓取或绕过第三方平台权限。首期支持用户拥有使用权的上传音频和可配置的授权音源；正式商业曲库以后通过同一个 Provider 接口接入。

## 已确认的用户流程

1. 用户继续使用现有首页搜索框或单曲搜索页查询歌曲。
2. 搜索结果的每一首歌增加独立播放按钮，点击后不离开搜索结果。
3. 可播放歌曲立即进入底部播放器并开始播放，同时加入当前队列。
4. 底部播放器在首页、搜索结果、制作页和作品库之间保持状态。
5. 点击底部封面或歌曲信息，打开完整播放页；点击“制作同款周边”进入现有单曲制作页，并复用当前歌曲资料。
6. 没有可用音频的歌曲保留制作入口，播放按钮显示不可播放状态，并提供“导入已授权音频”的入口。

## 音源边界

### 首期可播放来源

- 用户上传且确认有权使用的 MP3、M4A、AAC、WAV、OGG 或 FLAC 文件。
- 服务器配置的授权音频清单。清单使用 `source + trackId` 作为稳定键，映射到本地文件或允许代理的 HTTPS 地址。
- 后续正式曲库 Provider 返回的试听或完整播放地址；前端不感知具体供应商。

### 首期不做

- 不把当前 QQ 音乐和网易云音乐的匿名搜索接口当作完整歌曲播放源。
- 不抓取、解析或持久化受保护的第三方音频地址。
- 不在没有授权状态时把“可搜索”误标为“可完整播放”。

## 后端结构

### `PlaybackProvider`

新增独立播放服务模块，避免把音频逻辑继续堆进 `workbench/server.py`。统一接口：

```python
class PlaybackProvider:
    def resolve(self, source: str, track_id: str) -> PlaybackAsset | None: ...
```

`PlaybackAsset` 包含：

- `trackKey`: `source:trackId`
- `url`: 浏览器可访问的同源地址
- `kind`: `full` 或 `preview`
- `mimeType`
- `durationMs`（允许为空）
- `provider`
- `expiresAt`（允许为空）

首期实现两个 Provider：

- `LocalAudioProvider`：读取上传音频索引并通过同源 `/media/audio/...` 输出，支持 HTTP Range。
- `ManifestPlaybackProvider`：读取服务器配置的授权音源清单；本地文件仍由本服务输出，HTTPS 远程地址只在允许域名中代理。

以后接入商业曲库时增加 Provider，不改变播放器 UI 和队列模型。

### API

- `GET /api/playback?source=<source>&id=<trackId>`
  - 成功：返回 `playable: true`、播放资源、歌曲资料。
  - 无音源：返回 HTTP 200 与 `playable: false`、明确原因；搜索和制作仍可用。
- `POST /api/audio/upload?source=<source>&id=<trackId>&name=<filename>`
  - 上传用户拥有权利的音频，限制类型与大小，写入本地音频库并更新索引。
- `GET /media/audio/<assetId>`
  - 同源输出音频，正确处理 `Range`、`206 Partial Content`、`Content-Type` 和缓存头，支持拖动进度。

现有 `/api/song` 与 `/api/artist` 返回的每首歌曲补充 `trackKey` 与 `playbackState`。`playbackState` 仅表示后端已知状态：`playable`、`unavailable` 或 `unknown`。前端点击时仍以 `/api/playback` 的实时结果为准。

## 前端结构

### 搜索结果

- 单曲搜索表格和歌手热门歌曲表格的第一列增加圆形播放按钮。
- 当前播放歌曲显示暂停按钮和轻量高亮；选中用于制作的样式继续独立存在。
- 点击歌曲正文仍执行原来的选择/制作行为，点击播放按钮只控制播放，两个点击区域不冲突。
- 顶部搜索联想结果增加小型播放按钮；无可播放状态时仍可进入单曲结果页。

### 底部播放器

固定在页面底部，高度在桌面端约 76px，包含：

- 左侧：封面、歌名、歌手、音源类型。
- 中间：上一首、播放/暂停、下一首、播放模式；下方为当前时间、进度条和总时长。
- 右侧：音量、播放队列、打开完整播放页。
- 没有当前歌曲时整条播放器隐藏，不占页面空间。

播放器状态在单页工作台内保持；页面刷新后只恢复队列和歌曲资料，不自动播放，避免浏览器自动播放限制。

### 完整播放页

使用工作台内部全屏面板，不打开新站点。包含大封面、歌曲资料、进度控制、歌词区域、当前队列，以及“制作同款周边”按钮。

首期歌词区域支持三种状态：已接入歌词、歌词加载中、暂无歌词。歌词缺失不影响播放。

### 播放队列

- 点击任一播放按钮时，将当前搜索结果作为临时队列，并从该歌曲开始。
- 支持列表循环、单曲循环、随机播放。
- 队列抽屉支持点击切歌、移除单曲、清空队列。
- 当前歌曲被移除时播放下一首；清空后停止播放并隐藏底部播放器。

### 导入音频

当歌曲只有元数据、没有可播放资源时，显示简短弹层：

- 说明“已找到歌曲资料，但当前没有可播放音源”。
- 提供“导入已授权音频”按钮。
- 上传完成后自动绑定当前 `trackKey` 并立即播放。
- 不改变歌曲封面、歌名、歌手与后续制作数据。

## 状态与错误处理

- 浏览器拒绝自动播放：播放器保持暂停并提示用户点击播放，不重复弹窗。
- 音频请求超时或过期：重新调用 `/api/playback` 一次；仍失败则停止并显示错误。
- 当前歌曲不可播放：不自动跳过用户主动点击的歌曲；给出导入入口。队列自动续播遇到不可播放项时跳过，并在队列中标记。
- 上传格式不支持、文件过大或文件损坏：服务端拒绝并返回中文原因，原歌曲状态不变。
- 封面加载失败：使用现有音符占位，不影响音频。
- 切换页面或进入制作：音频不中断；关闭完整播放页只关闭面板，不停止音乐。

## 移动端适配

- 底部播放器缩为封面、歌名、播放/暂停、下一首四个主要元素；进度条保留为顶部细线。
- 完整控制、音量和队列进入底部抽屉。
- 完整播放页使用单列布局，封面尺寸随视口缩放。
- 所有播放按钮至少 44×44 CSS 像素，并提供 `aria-label`。

## 数据与隐私

- 上传音频保存在工作台服务器，不写入 Git 仓库。
- 音频索引只保存必要的 `trackKey`、文件路径、MIME、大小、创建时间和来源说明。
- 后续上线时，音频库与作品库分开备份和权限控制。
- 页面不得暴露第三方密钥、用户令牌或服务器绝对路径。

## 验收标准

1. 搜索任意歌曲时，结果行存在明确的播放入口和原有制作入口。
2. 已绑定音频的歌曲可开始播放，底部播放器能暂停、续播、拖动进度、调节音量和切换上下首。
3. 切换到制作页或作品库后播放不中断。
4. 完整播放页能显示当前歌曲和队列，并可一键进入该歌曲的现有制作流程。
5. 无音源歌曲不会假装播放；导入合法音频后无需重新搜索即可立即播放。
6. 列表循环、单曲循环和随机播放行为正确，刷新后不自动出声。
7. 音频端点支持 Range；拖动到歌曲中部后能从目标位置继续播放。
8. 原有单曲制作、热门批量制作、打印和作品库测试继续通过。
9. 桌面端与窄屏下没有播放器遮住主要按钮、弹层或滚动内容。

## 测试策略

- 后端单元测试覆盖音源解析、上传校验、索引持久化、Range 请求和不可播放响应。
- 前端结构测试覆盖播放按钮、底部播放器、完整播放页、导入弹层与制作跳转。
- 浏览器端到端测试使用仓库内生成的短音频夹具，验证播放、暂停、拖动、切歌、队列和跨页面持续播放。
- 回归运行现有 Python 测试，确认商品制作能力没有变化。
